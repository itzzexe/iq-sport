# مجموعة العراق الرياضية — IQ Sports Group

موقع المجموعة الرسمي (عربي / إنجليزي) مع نظام إدارة محتوى مفتوح المصدر بالكامل.
كل ما يظهر في الموقع — النصوص، الصور، الأقسام، الفروع، الإحصائيات، الكادر، البطولات، نصوص الأزرار، وبيانات محركات البحث — يُدار من لوحة التحكم على `/admin` دون أي تعديل في الكود.

| الطبقة | التقنية | الترخيص |
|---|---|---|
| الموقع | [Next.js 16](https://nextjs.org) + React 19 + Tailwind CSS 4 | MIT |
| الطبقة ثلاثية الأبعاد والتمرير | Three.js + React Three Fiber (المشاهد)، GSAP ScrollTrigger + Lenis (التمرير القصصي) | MIT |
| نظام إدارة المحتوى | [Payload CMS 3](https://payloadcms.com) (يعمل داخل التطبيق نفسه على `/admin`) | MIT |
| قاعدة البيانات | SQLite (ملف واحد — لا يحتاج خادماً) عبر libSQL؛ يمكن الانتقال إلى Turso أو Postgres | — |
| الصور | تُرفع من لوحة التحكم وتُولَّد منها مقاسات WebP تلقائياً (sharp) | — |

## التشغيل لأول مرة

**المتطلبات:** Node.js 20.9 أو أحدث.

```bash
npm install
cp .env.example .env        # ثم عدّل القيم (انظر أدناه)
npm run dev                 # http://localhost:3000  — لوحة التحكم: http://localhost:3000/admin
```

عند أول تشغيل يحدث الآتي تلقائياً:

1. تُنشأ قاعدة البيانات `data/iq-sport.db` وتُطبَّق عليها بنية الجداول (migrations).
2. تُعبَّأ بكل محتوى الموقع الحالي بلغتيه (النصوص من ملف الشركة، الصور، الفروع، الأقسام، المدربون، الإحصائيات…).
3. تفتح `/admin` فتطلب منك إنشاء **أول حساب مدير** — هذا الحساب يملك كل الصلاحيات.

> إن أردت إعادة التعبئة من الصفر: أوقف الخادم ثم `npm run seed:reset` (يحذف كل المحتوى والصور المرفوعة ويعيد المحتوى الأولي).

### ملف `.env`

| المتغير | الوصف |
|---|---|
| `DATABASE_URL` | `file:./data/iq-sport.db` للملف المحلي، أو `libsql://….turso.io` لقاعدة بعيدة |
| `DATABASE_AUTH_TOKEN` | مطلوب فقط مع Turso |
| `PAYLOAD_SECRET` | مفتاح تشفير الجلسات — نص عشوائي طويل (32 حرفاً فأكثر). **لا تشاركه ولا تغيّره بعد الإطلاق** (تغييره يُخرج جميع المستخدمين) |
| `NEXT_PUBLIC_SERVER_URL` | رابط الموقع الكامل بدون `/` في النهاية، مثل `https://iqsportsgroup.iq` |
| `PREVIEW_SECRET` | سرّ المعاينة الحية من لوحة التحكم — نص عشوائي |
| `PAYLOAD_SEED` | ضعه `false` لتعطيل التعبئة التلقائية عند أول تشغيل |

## دليل لوحة التحكم

تفتح لوحة التحكم على `/admin`. اللغة تتبع لغة المتصفح ويمكن تغييرها من صورة الحساب ← Language. في أعلى كل صفحة يوجد محدّد **Locale** (العربية / الإنجليزية): كل حقل نصي يُحفظ لكل لغة على حدة، والصور والأرقام والروابط مشتركة بين اللغتين.

### أين أجد كل شيء؟

| ما تريد تعديله | مكانه في لوحة التحكم |
|---|---|
| واجهة الصفحة الرئيسية (العنوان، صورة الخلفية، الأزرار) | **الصفحات ← الصفحة الرئيسية ← تبويب Hero** |
| النبذة التعريفية (الفقرات، الصورة، الركائز) | **الصفحة الرئيسية ← تبويب النبذة التعريفية** |
| مربعات الأقسام الستة (الترتيب، الأسماء، الصور، إخفاء أحدها) | **الصفحة الرئيسية ← تبويب شبكة الأقسام** |
| نصوص «تواصل معنا» ورسالة نجاح الحجز | **الصفحة الرئيسية ← تبويب تواصل معنا والحجز** |
| الأقسام (بادل، سلة، تنس، كرة قدم، صالة، مسبح…) وصفحة كل قسم | **المحتوى ← الأقسام** |
| الفروع ومواقعها على الخريطة وأرقامها | **المحتوى ← الفروع** (موقع النقطة على الخريطة: نسبة مئوية أفقياً/عمودياً) |
| المدربون | **المحتوى ← الكادر التدريبي** |
| البطولات السابقة والقادمة والدورات التدريبية | **المحتوى ← البطولات والدورات التدريبية** |
| الأرقام والإحصائيات و«لماذا نحن» | **الصفحات ← صفحة الإحصائيات** |
| نص الرؤية والقيم | **الصفحات ← صفحة الرؤية** |
| عناوين ومقدّمات الصفحات الداخلية | **الصفحات ← (الصفحة المطلوبة)** |
| رقم الهاتف، واتساب، البريد، العنوان، حسابات التواصل | **الإعدادات ← إعدادات الموقع ← التواصل** |
| روابط القائمة العلوية، نص التذييل، سطر الحقوق | **إعدادات الموقع ← التنقل** |
| رابط الموقع، العنوان والوصف الافتراضيان، الكلمات المفتاحية، صورة المشاركة، السماح بالفهرسة، رمز Google Search Console | **إعدادات الموقع ← محركات البحث (SEO)** |
| أي نص زر أو عنوان صغير في الموقع | **إعدادات الموقع ← النصوص** (اترك الحقل فارغاً للنص الافتراضي) |
| عنوان ووصف وصورة صفحة معيّنة في نتائج البحث | تبويب **SEO** داخل تلك الصفحة أو القسم أو البطولة |
| طلبات الحجز الواردة من الموقع | **الطلبات ← طلبات الحجز** (حدّث الحالة: جديد / تم التواصل / مؤكّد / ملغى) |
| الصور المرفوعة | **النظام ← الوسائط** (اكتب «النص البديل» لكل صورة — مهم لمحركات البحث) |
| حسابات المديرين | **النظام ← المستخدمون** |

### قواعد الإدخال

- **الحقول المعلّمة بنجمة (\*) إلزامية بالعربية فقط.** أي حقل يُترك فارغاً في النسخة الإنجليزية يعرض النص العربي تلقائياً، فيمكن ترجمة العنوان وحده ونشر الصفحة دون ترجمة كل الفقرات.
- **المعرّف في الرابط (slug)** بأحرف إنجليزية صغيرة وأرقام وشرطات فقط (`padel`, `summer-cup-2026`). إن تُرك فارغاً واسم العنصر بالإنجليزية يُشتق تلقائياً؛ مع الأسماء العربية يجب كتابته. لا يمكن النشر بدونه.
- **ربط المدرب بالقسم** يتم من أيّ الجهتين: حقل «القسم» في صفحة المدرب، أو قائمة «المدربون» في صفحة القسم — وفي الحالتين يظهر في صفحة القسم وفي صفحة الكادر.
- الصور: الأبعاد الأصغر تُولَّد تلقائياً ولا تُكبَّر الصور الصغيرة؛ للواجهة الرئيسية ارفع صورة بعرض 1920 بكسل فأكثر.

### النشر والمسودّات

الأقسام والفروع والمدربون والبطولات تدعم **المسودّات**: الحفظ كمسودة لا يُظهر شيئاً في الموقع؛ زر **Publish** ينشر، وزر **Unpublish** يخفي. الصفحات والإعدادات تُحفظ مباشرة.
أي حفظ في لوحة التحكم ينعكس على الموقع خلال ثانية — لا حاجة لإعادة البناء أو التشغيل.

### المعاينة الحية

أيقونة العين أعلى صفحة التحرير تفتح الصفحة الفعلية بجانب النموذج، وتتحدث مع كل حفظ — بما فيها المسودّات غير المنشورة (تظهر لك وحدك بصفتك مسجّل الدخول).

### الصور

- الصورة الرئيسية للواجهة: **الصفحة الرئيسية ← Hero ← صورة الخلفية** (صورة عريضة 1920 بكسل فأكثر). الصورة الحالية مؤقتة (لقطة جوية من ملف الشركة) إلى أن تُستبدل.
- صورة المشاركة الافتراضية (فيسبوك/واتساب/X): **إعدادات الموقع ← SEO ← صورة المشاركة** — مقاس 1200 × 630.
- الحد الأقصى لحجم الملف 15 ميغابايت؛ تُولَّد المقاسات الأصغر تلقائياً.

## الخطوط

الخطوط مضمّنة في الموقع (لا تُحمَّل من خدمات خارجية) بصيغة WOFF2 من ملفات الهوية:

| الاستخدام | الخط | الملف |
|---|---|---|
| العناوين اللاتينية | Varien | `src/fonts/Varien.woff2` |
| النصوص اللاتينية | Acumin Variable Concept (محور الوزن 100–900) | `src/fonts/AcuminVariableConcept.woff2` |
| النصوص العربية | IBM Plex Sans Arabic — Thin 100 / Regular 400 / Medium 500 | `src/fonts/IBMPlexSansArabic-*.woff2` |
| العناوين العربية | انظر الملاحظة | |

> **ملاحظة مهمة عن العناوين العربية:** ملف `DIN Alternate Bold.ttf` المُرسَل هو نسخة DIN اللاتينية من Apple ولا يحتوي على أي حرف عربي (تم فحص جدول الحروف: صفر حرف عربي). الخط الذي يحدده دليل الهوية للعناوين العربية هو **DIN Next Arabic Bold** وهو ملف مختلف.
> الحل المطبَّق: العناوين العربية تُعرض بـ IBM Plex Sans Arabic Medium (أثقل وزن عربي متوفر)، مع إبقاء DIN Alternate Bold أولاً في سلسلة الخط ليعرض الكلمات اللاتينية والأرقام داخل العناوين العربية.
> عند توفر ملف DIN Next Arabic Bold: ضعه في `src/fonts/` وعدّل مسار `dinArabic` في [`src/lib/fonts.ts`](src/lib/fonts.ts) — لا شيء آخر يحتاج تعديلاً.

## الطبقة ثلاثية الأبعاد والتمرير القصصي

كل صفحة تحمل مشهد WebGL خلف المحتوى، مع تمرير ناعم (Lenis) يقود GSAP ScrollTrigger:

| الصفحة | المشهد |
|---|---|
| الرئيسية وباقي الصفحات الداخلية | **شعار المجموعة ثلاثي الأبعاد** (الشريطان مبثوقان من المسارات الأصلية للهوية) يتموضع مقابل النص ويتراجع مع التمرير + حقل جسيمات بألوان الهوية |
| صفحة الأقسام (`/divisions`) | **الجولة**: رحلة ثلاثية الأبعاد متصلة في مشهد واحد — تبدأ بالشعار ثلاثي الأبعاد ثم تطير الكاميرا بسلاسة من محطة إلى محطة، وكل قسم يُعرض بمشهده الخاص (سطح كرات البادل، كرة السلة المرتدة، ملعب التنس المرسوم بالضوء، كرة القدم، بار الحديد، سطح الماء) مع نصه ورقمه الضخم ورقمه البارز وفروعه. مسار جانبي بالمحطات للقفز بينها، وخط نهاية بفهرس الأقسام وزر الحجز. تعمل على الهاتف بنفس الأسلوب. المحطات من الأقسام المنشورة في نظام إدارة المحتوى (المشهد يُختار من حقل الأيقونة) |
| `/divisions/padel` | سطح من آلاف الكرات المُنسَّخة يتموّج ويغور تحت المؤشر |
| `/divisions/gym` | بار حديد بأقراص تتباعد مع التمرير |
| `/divisions/swimming` | سطح ماء أسود بموجات وكاوستيك أخضر |
| `/divisions/tennis` | ملعب بأبعاده الحقيقية مرسوم بالضوء وكرة تعبر الشبكة |
| `/divisions/football` | كرة تتفكك ألواحها مع التمرير |
| `/divisions/basketball` | كرة برتقالية ترتد بانضغاط واستطالة |

المشهد يُختار من حقل **الأيقونة** في القسم (بادل، صالة، سباحة، تنس، كرة قدم، كرة سلة). قسم جديد بأيقونة «شعار المجموعة» يحصل على مشهد الشعار.
إضافةً إلى ذلك: لودر بشعار المجموعة عند الدخول، عناوين تصعد من أقنعة قصّ، شريط الأقسام المتحرك المتأثر بسرعة التمرير، بارالاكس على الصور والخريطة، وكشف نص الرؤية كلمةً كلمة.

الطبقة ثلاثية الأبعاد تُحمَّل بعد أول رسم ولا تُحمَّل إطلاقاً إذا لم يتوفر WebGL أو طلب المستخدم تقليل الحركة — الموقع يبقى مقروءاً بالكامل. عدد الجسيمات ودقة الأشكال تتكيف مع قدرة الجهاز (`src/lib/perf.ts`).

## البنية

```
src/
  app/(frontend)/[lang]/     الصفحات العامة: / (ar) و /en — الرئيسية، divisions، branches، statistics، team، tournaments، vision
  app/(payload)/             لوحة التحكم /admin وواجهة REST /api (مولَّدة من Payload)
  app/robots.ts, manifest.ts, (frontend)/sitemap.ts
  proxy.ts                   يوجّه / إلى العربية و /en إلى الإنجليزية (رابط واحد لكل صفحة)
  payload.config.ts          إعداد نظام إدارة المحتوى (اللغات، الصلاحيات، SEO، المعاينة)
  payload/collections/       الأقسام، الفروع، المدربون، البطولات، طلبات الحجز، الوسائط، المستخدمون
  payload/globals/           إعدادات الموقع، الصفحة الرئيسية، الصفحات الداخلية
  payload/seed/              المحتوى الأولي وآلية التعبئة التلقائية
  migrations/                بنية قاعدة البيانات (تُطبَّق تلقائياً)
  webgl/                     مشهد Three.js: الشرائط، الجسيمات، حلقة الأقسام، مشاهد الأقسام الستة، الشيدرات
  components/motion/         Lenis + ScrollTrigger، نشر مراحل التمرير للمشهد، البارالاكس، تركيب المشهد لكل مسار
  components/                مكوّنات الواجهة (الهيدر، الفوتر، البطاقات، النموذج، الخريطة، اللودر…)
  lib/                       قراءة المحتوى مع التخزين المؤقت (cms.ts)، اللغات (i18n.ts)، SEO (seo.ts)، الخطوط
  actions/booking.ts         استقبال طلبات الحجز وتخزينها في نظام إدارة المحتوى
```

**كيف يصل التعديل إلى الموقع:** الصفحات مُولَّدة مسبقاً (ثابتة وسريعة) وتُقرأ بياناتها من نظام إدارة المحتوى مع تخزين مؤقت. أي حفظ في لوحة التحكم يستدعي إعادة التحقق (revalidation) فتُعاد صياغة الصفحات عند الطلب التالي.

**اللغتان:** العربية على الجذر `/` والإنجليزية تحت `/en`، مع `hreflang` و`canonical` صحيحين لكل صفحة، وخريطة موقع تضم اللغتين.

## قاعدة البيانات

- الملف: `data/iq-sport.db` (مع ملفي `-wal` و`-shm` أثناء التشغيل). **هذا الملف + مجلد `public/media` هما كل بيانات الموقع — انسخهما احتياطياً دورياً.**
- بنية الجداول تُدار بملفات الهجرة في `src/migrations/` وتُطبَّق تلقائياً قبل `dev` و`build` وعند تشغيل خادم الإنتاج.
- عند تعديل حقول نظام إدارة المحتوى في الكود (إضافة حقل مثلاً): `npm run migrate:create اسم-وصفي` ثم `npm run generate:types`، وارفع ملفات الهجرة الجديدة مع الكود.
- للانتقال إلى **Turso** (SQLite سحابي): غيّر `DATABASE_URL` و`DATABASE_AUTH_TOKEN` فقط. للانتقال إلى Postgres: استبدل `@payloadcms/db-sqlite` بـ `@payloadcms/db-postgres` في `payload.config.ts` وأعد إنشاء الهجرة.

## النشر على خادم (VPS)

```bash
git clone … && cd iq-sport
npm ci
cp .env.example .env         # عدّل: PAYLOAD_SECRET, PREVIEW_SECRET, NEXT_PUBLIC_SERVER_URL=https://your-domain
npm run build                # يطبّق الهجرات، يعبّئ المحتوى الأولي إن كانت القاعدة فارغة، ويبني الموقع
npm start                    # يستمع على المنفذ 3000
```

- شغّله كخدمة دائمة (PM2: `pm2 start npm --name iq-sport -- start`، أو systemd) خلف Nginx/Caddy مع HTTPS.
- المجلدات التي يجب أن تبقى بين عمليات النشر: `data/` و `public/media/`.
- بعد تغيير النطاق: حدّث `NEXT_PUBLIC_SERVER_URL` في `.env` **و** حقل «رابط الموقع الكامل» في إعدادات الموقع ← SEO، ثم أعد التشغيل.
- على منصات بلا قرص دائم (Vercel وأمثالها): استخدم Turso لقاعدة البيانات ومزوّد تخزين للصور (`@payloadcms/storage-s3` أو `@payloadcms/storage-vercel-blob`) — التغيير ينحصر في `payload.config.ts`.

### قائمة ما قبل الإطلاق

- [ ] `PAYLOAD_SECRET` و`PREVIEW_SECRET` قيم عشوائية جديدة (لا تستخدم قيم التطوير).
- [ ] إعدادات الموقع ← التواصل: رقم الهاتف الحقيقي، واتساب بصيغة `9647XXXXXXXXX`، البريد، روابط إنستغرام/فيسبوك.
- [ ] إعدادات الموقع ← SEO: رابط الموقع الكامل، رمز التحقق من Google Search Console، تفعيل «السماح بالفهرسة».
- [ ] الصفحة الرئيسية ← Hero: صورة الخلفية النهائية.
- [ ] الفروع: الإحداثيات الجغرافية وروابط خرائط Google لكل فرع (تظهر في نتائج البحث المحلية).
- [ ] البطولات: حذف النموذجين التوضيحيين (محفوظان كمسودتين) وإضافة البطولات الحقيقية.
- [ ] إرسال `https://your-domain/sitemap.xml` إلى Google Search Console.

## حلّ المشاكل

**`SyntaxError: Unexpected non-whitespace character after JSON` على كل الصفحات في وضع التطوير** — ليس خطأً في الموقع؛ ملف `.next/dev/prerender-manifest.json` الذي يكتبه خادم Next.js تلف لأن عدة صفحات تُرجمت في اللحظة نفسها (مثلاً عند استعادة المتصفح لعدة تبويبات دفعة واحدة)، ومزامنة OneDrive أو برامج الحماية تزيد احتمال ذلك. `npm run dev` يفحص هذه الملفات تلقائياً قبل التشغيل ويحذف الذاكرة المؤقتة إن كانت تالفة (`src/scripts/heal-dev-cache.ts`). إن حدث الخطأ والخادم يعمل: أوقفه بـ `Ctrl+C` ثم `npm run dev` (أو `npm run dev:clean`). يُفضَّل استثناء `.next` و`node_modules` و`data` من مزامنة OneDrive، أو نقل المشروع خارج مجلد OneDrive.

## ملاحظات أمنية

- لوحة التحكم محمية بتسجيل الدخول؛ الطلبات عبر REST من متصفح تتطلب رأس Origin صحيحاً (حماية CSRF)، ومن الخوادم تتطلب `Authorization: JWT <token>`.
- طلبات الحجز لا يمكن إنشاؤها عبر الواجهة العامة (`POST /api/bookings` مرفوض)، بل عبر النموذج فقط مع تحقق من المدخلات وفخّ للروبوتات وتحديد لعدد الطلبات لكل عنوان IP.
- لا يوجد مزوّد بريد إلكتروني مضبوط؛ رسائل استعادة كلمة المرور تُطبع في سجل الخادم. لإرسالها فعلياً أضف `@payloadcms/email-nodemailer` في `payload.config.ts`.

## English summary

Bilingual (Arabic default at `/`, English at `/en`) marketing site for IQ Sports Group, built with Next.js 16 and a fully open-source Payload CMS 3 admin at `/admin`. A persistent WebGL layer (Three.js / React Three Fiber) sits behind every page — the extruded 3D brand mark and particle field, a pinned ring of venue panels on the divisions page, and a bespoke scene per sport on each division page — choreographed by Lenis smooth scrolling and GSAP ScrollTrigger. Every string, image, list and SEO field is editable in the CMS; changes go live within a second via on-demand revalidation. Pages are statically prerendered, ship `hreflang`/canonical/OpenGraph/JSON-LD, a bilingual sitemap, robots and a web manifest. Bookings submitted from the site land in the CMS. Run `npm install && cp .env.example .env && npm run dev`; the database is migrated and seeded automatically on first start, then create the first admin at `/admin`. Back up `data/` and `public/media/`.
